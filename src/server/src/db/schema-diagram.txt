================================================================================
                            RELATIONSHIPS
================================================================================

logs.issue_id          ───►  issues.issue_id         (many logs per issue)
issues.bug_id          ───►  bugs.bug_id             (one bug per issue)
issues.matched_sig_id  ───►  *_signatures.sig_id     (matched signature)
bugs.resolution_id     ───►  resolutions.res_id      (bug fix)
*_sigs.resolution_id   ───►  resolutions.res_id      (known fix)
config_notif.config_id ───►  diagnostic_configs.id   (config that changed)
config_notif.bug_id    ───►  bugs.bug_id             (why config changed)
config_notif.issue_id  ───►  issues.issue_id         (why config changed)


================================================================================
                         ENGINEER WORKFLOW
================================================================================

To find logs for an Issue:
  SELECT * FROM logs WHERE issue_id = ?

To find logs for a Bug:
  SELECT l.* FROM logs l
  JOIN issues i ON l.issue_id = i.issue_id
  WHERE i.bug_id = ?


================================================================================
                              DATA FLOW
================================================================================

1. Log arrives → creates Issue → creates Bug
2. Additional logs for same issue → linked via issue_id
3. Signature added with Resolution
4. Issue matched to Signature → Issue status = "resolved"
5. Engineer views Issue → sees all logs + resolution


================================================================================
                      CONFIG NOTIFICATION WORKFLOW
================================================================================

  ENGINEER                          SYSTEM                         ADMIN
     │                                 │                              │
     │  1. Working on bug/issue        │                              │
     │  ───────────────────────►       │                              │

     │  2. Updates diagnostic_configs  │                              │

     │                          3. Auto-creates notification          │
     │                             status = "pending"                 │
     │                             links bug_id/issue_id              │
     │                             snapshots previous config          │
     │                                 │                              │
     │                                 │  4. Admin sees pending       │
     │                                 │     notification in dashboard│
     │                                 │  ◄────────────────────────── │
     │                                 │                              │
     │                                 │  5. Admin reviews change     │
     │                                 │     (sees diff, reason)      │
     │                                 │  ◄────────────────────────── │
     │                                 │                              │
     │                                 │  6. Admin deploys to:        │
     │                                 │     - Single machine         │

Status values: pending → acknowledged → deployed (or dismissed)
